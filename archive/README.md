# Chat Archive

`chat-archive.html` —— 单文件聊天记录存档。双击用浏览器打开就能用，不需要服务器、不联网、无依赖。

**一份 JSON 备份 = 一段对话。列表里放很多段，点开就是聊天界面。**

## 怎么用

1. 拖一个 `.json` / `.jsonl` / `.ndjson` 进来，确认一下哪个字段是「消息 / 谁说的 / 时间」，给这段对话起个名。
2. 存好后回到列表，像微信的会话列表一样一行一段，显示头像、标题、最后一句、条数、日期。
3. 点开 = 聊天界面：气泡、头像、日期分隔条、同一个人连续发言自动并排。
4. 右上角三个入口：搜索 / 成员 / 更多。

## 能力

- **多段对话**：导入多少段就存多少段，互不影响，重开浏览器还在。删除某一段只删那一段。
- **聊天界面**：默认气泡排版，可在「⋯ → 排版」切成平铺（群聊人多时更好读）。在「成员」里把某个人设为「我」，他的气泡就靠右。
- **成员**：每个人可以传头像（自动裁成 160×160）、改名。改成这段对话里已有的名字会把两个人合并成一个。头像按名字存，重新导入同一段对话还在。
- **图片 / 表情包**：消息里的图片会真的显示出来。三种来源都认：分段内容里的图片对象（`image_url` / `image` / `source` base64 等写法）、正文里的 markdown 图片 / `<img src>` / `data:` / 直链、以及**散落在同级其他字段里的地址**（`image` / `pic_url` / `attachments[].url` 这类，正文里根本没提也能捡回来）。
  没有扩展名的图床链接同样能显示 —— 普通链接先按链接渲染，同时悄悄试着加载一次，能加载出来就换成图片，加载不出来就还是链接，不靠猜扩展名。只还原协议安全（`http(s):` / `data:image/`）的地址。
  带描述词的表情包（`{type:'sticker', caption:'微笑', url:…}`）取地址而不是那两个字；**只有图片没有文字的消息不套气泡**，就是一张裸图；图片打不开时直接显示地址方便排查。默认最大边长 150px，改 `--img-max` 即可。
- **翻译 / 副文本**：一条消息带原文和译文时，映射里选上「翻译 / 副文本」即可。界面上**没有按钮** —— 直接点那条消息，译文就出现在原文下面（气泡里一条细线隔开的一行淡字），再点收起。不想一条条点就在「⋯ → 翻译」里选 `一直显示`，另有 `不显示`。**搜索能搜到译文**（译文和原文并在同一条里建索引），命中在译文里的结果会标出来。
- **多选 / 编辑**：长按（手机）或右键（桌面）任意一条进入选择模式 —— 只在左边出现一个小对勾，气泡本身不加任何选中样式。可以逐条点选、Shift 点选一段、或「全选」。选好后底部可以复制、导出这些条、删除；只选一条时可以直接编辑正文和译文。编辑和删除只改这个存档，原始 JSON 文件不动。
- **搜索**：先给一个结果列表（几十万条也是几十毫秒），点任意一条跳到它在对话里的位置并高亮；点标题栏的结果数可以回到结果列表。
- **看到哪儿了**：退出一段对话时，如果这次挪动超过一屏，会问一句要不要记住位置（可以勾「以后都这样」）。记住后列表上显示「读到 136/400」，再进去顶上有个「上次看到第 136 条 · 继续」的胶囊，点一下跳回去，不点 9 秒后自己消失。
- **全字段保留**：JSON 里的字段全部留着但默认不显示，对话界面就是干净的聊天。要看时在「⋯ → 每条下方的字段」里切「精简 / 全部」，或点某条消息展开右侧面板看全部字段和原始 JSON。
- **导出**：HTML 网页（双击就能看，自带懒加载、搜索、头像和你的自定义 CSS）、Markdown、JSON、纯文本。生成后给一个明确的保存面板 —— 手机上走系统分享（「存储到文件」），桌面直接下载。
- **外观与样式**：头像可选圆形或方形；自定义 CSS 实时生效，还能**存成预设**（记住这套 CSS 和头像形状）随时切换。导出的 HTML 用同一套类名，样式、头像形状、翻译折叠状态一起带走。

## 实测（Chromium / headless）

| 规模 | 解析 | 入库+打开 | 搜索 | 滚动 p50 | 常驻 DOM | 堆内存 |
|---|---|---|---|---|---|---|
| 3 千条 × 26 字段 | 0.2 s | 0.6 s | 10 ms | — | ~20 | — |
| 20 万条 / 21 MB | 0.5 s | 2.7 s | 16 ms | 38 ms | 20 | 98 MB |
| 100 万条 / 102 MB | 5.1 s | — | 19–56 ms | — | 24 | 133 MB |

气泡排版和平铺排版的滚动开销实测一样（p50 33.6 vs 33.4 ms）。

## 架构

```
一个 JSON 文件
   │  Worker: JSON.parse → 字段探测 → 你确认映射
   ▼
一段对话（IndexedDB）
   c:<id>:cols   times / senderIdx
   c:<id>:t:<n>  正文分块
   c:<id>:s:<n>  译文分块（有映射才建）
   c:<id>:r:<n>  整条原始 JSON 分块（可关）
   convs         会话索引（标题、头像用的成员表、末条预览…）
   │
   ├─► 列表页：只读 convs，不加载正文
   └─► 打开一段：整段进内存 → Fenwick 变高虚拟列表 + Worker 搜索索引
```

### 几个关键取舍

**会话是单位，不是人。** 第一版把「一个角色」当成一个档案袋，于是一段六个人的对话被拆成六个袋子，点进任何一个都只看得到一个人自言自语 —— 跟聊天软件正好相反。现在一份备份就是一段对话，人退回到会话内部的「成员」。

**译文并进同一条建索引。** 搜索索引里，每条是「原文 + U+0002 + 译文」，条与条之间才用 U+0001 分隔。这样一次 `indexOf` 就同时覆盖原文和译文，命中后二分定位仍然落到正确的那一条，不用维护第二套索引。

**搜索不建倒排索引。** 几十万条中文做倒排要 bigram 分词，索引比原文还大，构建还要数秒。改成 Worker 里把消息按块拼成大写字符串（每块 ≤ 2 万条 / 800 万字符）配 `Int32Array` 偏移表，用原生 `indexOf` 扫，命中后二分定位。中英文同一套逻辑，零构建成本。块内用 U+0001 分隔避免跨条误匹配。

**虚拟列表按实测高度走 Fenwick 树。** 先按字符数估高（每行字符数由采样的中西文比例推算，日期分隔条和连续发言各自加减），渲染后实测真高回写，并用锚点补偿滚动位置。前缀和与二分都是 O(log n)。总高超过 1500 万 px 时压缩滚动空间（浏览器对元素高度有上限），用 `scale` 在滚动坐标和虚拟坐标间换算。

**字段全留，但渲染时才解析。** 保留每条原始 JSON 才能做到一个字段不丢；展示侧不预先摊平成列，而是渲染到哪条才 `JSON.parse` 哪条（4000 条缓存）。可见的永远只有二三十条，所以「每条 25 个字段全展开」和「完全不显示」的滚动开销一样。

**导出要有个能落地的地方。** 手机浏览器（尤其 iOS Safari）对 blob 下载基本无效，文件生成了却没处去。现在生成后弹一个保存面板：能用 `navigator.share` 就走系统分享（「存储到文件」），否则直接下载，并留「在新标签打开」兜底。

**导出的页面必须在最差的情况下也能出内容。** 三条：① 内嵌的 JSON 里所有 `<` 一律转成 `\u003c` —— 只转 `</script` 是不够的，消息里一个 `<!--` 加一个 `<script` 就能让 HTML 解析器进入 double-escaped 状态，把剩下的全吞掉；② 开头几屏直接画出来，不等 `IntersectionObserver`，没有这个 API 就整篇渲染；③ 整个脚本裹在 try/catch 里，出错时在页面上显示具体报错，而不是留一个只剩搜索框的空壳。

### 踩过的坑

- **抽屉用 `translateX(100%)` 停在屏幕外，会把文档撑宽一个抽屉**。桌面看不出来，手机上浏览器为了塞下把整页缩放，于是「整个页面都坏了」。得由 `#chat` 兜住（`position:relative; overflow:hidden`）。
- **面板隐藏时 `clientWidth` 是 0**，ResizeObserver 会把它当成尺寸变化去重排，量出一堆错高度；再切回来就停在对话中间。隐藏时直接跳过。
- **同理，路由要先切再建视图** —— 在 `display:none` 状态下建列表，行高全是错的。
- **IndexedDB 里用游标清理 + 同事务写入会自毁**：游标的 `delete` 是在 `onsuccess` 里才排队的，排在 `put` 后面，把刚写进去的删掉。第一次保存因为库是空的看不出来。清理必须单独一个事务。
- **替换底层数组之前必须先让视图退出旧状态**：删除消息时先换数组再调用退出选择模式，而后者会触发按旧下标重排，`S.texts[gi]` 已经是 `undefined`，整个删除流程静默中断、遮罩卡住。顺序要反过来，并且估高函数对越界下标要有兜底。
- **`<span>` 里套 `<span>` 不会自动堆叠**，得显式 `display:block`，否则标题和副标题会挤成一行乱换行。
- **浮层要挂在内容区上，不是挂在整个页面上**：日期胶囊和「继续」胶囊原本相对 `#chat` 定位，而 `#chat` 包含标题栏，于是它们跑到标题底下，看不见也点不到。得套一层 `.chat-body`。
- **摊平分段内容时别用 `p.text || ''` 收尾**：没有 `text` 字段的部分（正好就是图片和表情包）会被静默吞成空字符串。同理，取值顺序不能让 `caption` 排在图片地址前面，否则带描述词的表情包只剩下那两个字。
- **别靠扩展名判断一个链接是不是图片**：真实图床地址大多没有扩展名（`i.imgur.com/abc123`），或者扩展名藏在参数里（`?format=jpg`），或者是一长串签名参数。靠正则猜必然漏。改成"先当链接显示，同时试加载一次"，让浏览器给答案。
- **图片地址未必在消息字段里**：很多导出把图片放在同级的 `image` / `pic_url` / `attachments[]`，只读映射到的那个字段就永远看不到图。

### 其他

- Worker 用 Blob URL 创建；被 `file://` 策略拦截时自动回退到主线程跑同一份代码。
- 花体字在线时用 Cormorant Garamond，离线退到 Didot / Bodoni / Georgia。
- 所有文本转义后再插入，`<script>`、`<img onerror>` 之类只按字面显示；高亮不破坏转义。
- 图标全是内联 SVG，没有 emoji。跟随系统深色模式，也可手动切换。
