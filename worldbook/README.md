# 世界书

原来是一个 4824 行的单文件，生成和存储混在一起。现在拆成两个页面：

| 页面 | 管什么 | 要不要 API |
|---|---|---|
| `index.html` 世界书生成器 | 生成、审查、评分、详细分析、修订、试运行、模型画像 | 要 |
| `library.html` 世界书库 | 自制区 / 导入区、查看、改名、导出、批量打包、整库备份 | 不要 |

两个页面**同源**，所以共用同一个 IndexedDB（`wbgen`）。生成器里「保存到世界书库」
存进去的书，书库那边刷新就能看见，反之亦然。

生成器唯一的存储出口就是那颗「保存到世界书库」按钮 —— 导出 txt / docx /
SillyTavern、改名、批量、整库备份全在书库那边。

## 文件

```
index.html    生成器的壳
library.html  书库的壳
style.css     两边共用的样式
core.js       共用内核：util / db / api / lexicon / rules / audit / prompt /
              diff / series / memory / profile / exporter / pipeline / 通用组件
gen.js        生成器的视图和外壳
lib.js        书库的视图和外壳
```

`core.js` 加载时不碰 DOM，所以两个页面谁先加载都一样。模块仍然挂在全局 `__M`
上，用法和拆分前完全一致（`__M['db']`、`__M['pipeline']`……）。

## 副模型现在做三件事

以前只有判断和评分，现在多了一段详细分析：

1. **逐条判定** —— 八条规则，每条 pass / warn / fail，必须引原文。
2. **评分** —— 和本地静态检查合并后的综合分。两者冲突时以本地为准。
3. **详细分析** —— 拿着评分和证据，回答审查报告回答不了的那部分：注进去之后
   模型大概会写成什么样、这些扣分项背后是不是同一个根因、只改一处该改哪里、
   哪些地方反而不要动。

**修订的时候，评分、逐条判定和这段分析会一起带给主模型**，所以它不是写给你
看完就算的 —— 主模型知道扣在哪、为什么扣。

分析怎么跑在「设置 → 审查与注入 → 详细分析」里选：

- **单独跑一次**（默认）—— 审查出结果之后再调一次副模型，把评分和证据喂回去。
  最深，代价是每版多一次调用。
- **挤在审查那次里** —— 审查的 JSON 里多一个 `analysis` 字段，不额外花钱。
  但模型是边判边写，分析会浅一些，长文本塞 JSON 也更容易解析失败。
- **不写** —— 修订时就只带评分和逐条结论。

分析这一步失败不影响审查：评分和逐条结论已经拿到手了，只会提示一句。
